# Native interaction parity

The library targets familiar mobile behavior in React web apps with the host app's branding and router. Evidence comes from official platform patterns, open-source implementations, browser tests, and separately recorded real-device sessions.

| Interaction | Reference behavior and source | Web implementation and next verification |
| --- | --- | --- |
| Bottom Sheet | Apple uses resizable [detents and a grabber](https://developer.apple.com/design/human-interface-guidelines/sheets/). Compose supports [partial sheets](https://developer.android.com/develop/ui/compose/components/bottom-sheets-partial) and [nested scroll](https://developer.android.com/develop/ui/compose/touch-input/scroll/nested-scroll-modifiers). [Vaul](https://github.com/emilkowalski/vaul) is MIT and marked unmaintained by its maintainer. [React Spring Bottom Sheet](https://github.com/stipsan/react-spring-bottom-sheet), [Base UI Drawer](https://base-ui.com/react/components/drawer) and [Ionic Sheet Modal](https://ionicframework.com/docs/api/modal) offer independently useful comparisons. | The visible viewport determines detents. The handle supports drag, tap and keyboard. Release uses recent movement so an initial hold does not suppress a flick, and an end pause clears momentum. Next evidence: content-to-sheet handoff, real keyboard behavior and per-device latency. |
| Adaptive Dialog | Apple describes [sheet presentations across device classes](https://developer.apple.com/design/human-interface-guidelines/sheets/). Base UI documents virtual-keyboard-aware drawer behavior. | Resize preserves the edited field and modal focus. A wide dialog fits within the measured visual viewport while a software keyboard can reduce it independently of the layout viewport. Browser tests inject that viewport change. Test actual keyboard, rotation and focus on devices. |
| Swipe Action | [SwiftUI](https://developer.apple.com/documentation/swiftui/view/swipeactions(edge:allowsfullswipe:content:)), [Compose SwipeToDismissBox](https://developer.android.com/develop/ui/compose/touch-input/user-interactions/swipe-to-dismiss) and [Ionic Item Sliding](https://ionicframework.com/docs/api/item-sliding) vary in whether a full swipe commits. | Reveal actions, then require explicit activation. Provide a one-tap and keyboard alternative. A two-finger pinch preserves browser zoom instead of revealing an action. Controlled `open` can coordinate rows. Logical start/end and actual Safari edge-gesture overlap need further evidence. |
| Pull to Refresh | [SwiftUI refreshable](https://developer.apple.com/documentation/swiftui/view/refreshable(action:)), [Compose Pull to Refresh](https://developer.android.com/develop/ui/compose/components/pull-to-refresh) and [Ionic Refresher](https://ionicframework.com/docs/api/refresher) tie triggers to a scroll surface and maintain pending feedback. | A local handle and refresh button avoid taking over document scroll. The live message remains outside the busy content. Disabling the trigger or beginning a second touch cancels a pending gesture. Host-scroll and browser-refresh arbitration still need device validation. |
| Action Sheet | [Apple Action Sheets](https://developer.apple.com/design/human-interface-guidelines/action-sheets/), [Ionic Action Sheet](https://ionicframework.com/docs/api/action-sheet) and [W3C dialog focus guidance](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) cover explicit cancel, short choices and safe initial focus. | A content-sized dialog keeps Cancel separate, restores focus and dispatches only explicit enabled choices. Selection order and follow-up belong to the app. Anchored tablet popovers and touch/assistive technology remain separate validation tasks. |
| Bottom Navigation | [Apple Tab Bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars), [Compose Navigation Bar](https://developer.android.com/develop/ui/compose/components/navigation-bar) and [Ionic navigation](https://ionicframework.com/docs/react/navigation) illustrate stable labels, current state and per-destination history. | Use native links, page state and safe-area padding. The host router owns per-destination navigation stacks. Check home indicators, landscape and standalone PWA behavior on devices. |

| Next candidate | First behavior to verify | References |
| --- | --- | --- |
| Swipe Pager | Commit the page when scrolling settles. Provide previous and next buttons and verify reduced motion, RTL and reflow. | [Compose Pager](https://developer.android.com/develop/ui/compose/layouts/pager), [CSS Scroll Snap](https://www.w3.org/TR/css-scroll-snap-1/), [Embla](https://www.embla-carousel.com/) |
| Context Menu | Provide a visible button and keyboard shortcut. Cancel a long press when the user starts scrolling and preserve text and link context. | [Apple Context Menus](https://developer.apple.com/design/human-interface-guidelines/context-menus/), [Radix Context Menu](https://www.radix-ui.com/primitives/docs/components/context-menu) |
| Wheel Picker | Keep a plain selection path and announce the committed value after the wheel settles. | [SwiftUI WheelPickerStyle](https://developer.apple.com/documentation/SwiftUI/WheelPickerStyle) |
| Reorderable List | Keep stable item identity and add move controls, focus preservation and position announcements. | [SortableJS](https://github.com/SortableJS/Sortable), [WCAG on dragging movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements) |

Browser gesture arbitration constrains native history gestures, browser pull-to-refresh, pinch and platform motion. Record the browser and host container when comparing a result.
